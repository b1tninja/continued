## 3. What the pull requests change

#746, the approval prompt:

1. The toolbar says "command" only when every waiting call is a terminal command, "action" otherwise; each Accept and Reject names its own call; Accept all has a tooltip with the count.
2. Always allow shows the whole rule it would save, wrapped, with the sentence "A safety check would still ask about this. Saves the rule:" as text in the page; a refusal wraps instead of being cut.
3. A held command cut in the loop inbox ends with "… [N more characters not shown; Allow covers the whole call]".
4. The card writes hidden and direction-changing characters out as `⟦U+202E⟧` and says how many there are. Tabs, line feeds, CRLF line ends and the joiners emoji need are left alone.

## 4. Principles applied

1. **The prompt is the contract.** What is shown at the moment of approval is what runs and what is saved: never cut without saying so, never behind a tooltip, never a character that draws as nothing.
2. **Name the thing by what it is.** A file read is not a command; a button that clears state is not "Continue".
3. **One word per idea, everywhere.** The same state has the same word on the card, in the tree, in the audit list and in the CLI.
4. **The safe action is the easy one.** A wider grant (Always allow, Accept all, Share everything) costs one more look than a narrow one, and is never the first or the heaviest button.
5. **An error says what happened and what the next step does.** One line of cause, no stack, and a button whose label is its effect.
6. **Narrow first.** Text is written to fit 300 px; where it cannot, it wraps; it does not truncate anything a decision rests on.
7. **Calm.** No "Oops", no exclamation marks, no alarm colour for a state that is merely off.
8. **No new machinery for accessibility.** No new `aria-live` regions; existing roles, the existing announcer, text instead of `title`.
