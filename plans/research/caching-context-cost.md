# Prompt caching, context and cost: what the providers document, and what we do

Status: research, 2026-11-11 (DRAFT, extended in later commits). Docs only: no code, no ROADMAP edit, no model call was made. Tracks C, J, Z and the compaction rows of V. Every provider fact below was fetched on 2026-11-11 unless a row says otherwise; none is older than six months. Where a page could not be read, or a fetch summary contradicted itself, the row says "unverified".

## 1. Summary

1. The cache table (`packages/llm-info/src/promptCache.ts`) agrees with Anthropic's and AWS's current minimums, lifetimes and checkpoint counts row for row. The risk is not wrong rows; it is what the code does not model.
2. Seven concrete mismatches are listed in section 7. The three that cost money or mislead: OpenAI GPT-5.6 and later bill cache writes (1.25x for 30 minutes, 2.5x for 12 hours) and our OpenAI price table has no write rate; the miss notice names no cause for changes Anthropic says rebuild the messages cache (thinking or effort settings, `tool_choice`, images appearing or disappearing); and the local-server "warm" window of 15 minutes is a guess that Ollama's documented default unload time may contradict (section 3.7, to be checked).
3. Token counts we compute locally (js-tiktoken or the llama tokenizer, `core/llm/countTokens.ts`) are estimates for every Claude model, and Anthropic says Claude 4.7 and later (Fable, Mythos, Opus 4.7 and up) count about 30 percent more tokens than earlier models for the same text. Anthropic's `count_tokens` is free and is itself "an estimate"; Bedrock's `CountTokens` says it matches the charged count.
4. Tool deferral on Anthropic's own API is cache-safe by construction (discovered tools arrive as `tool_reference` blocks in the messages, the prefix is untouched), but it does not exist on Bedrock Converse, which is where this fork's Claude traffic goes. Our client-side `search_tools` has to pay one prefix rewrite per activation; section 4 gives the break-even.
5. Context management that exists server-side on Bedrock today: context editing (beta header `context-management-2025-06-27`, Bedrock listed). Server-side compaction and programmatic tool calling are not listed for Bedrock Converse.

Notes that matter for design:

- Concurrency: Anthropic says "A cache entry only becomes available after the first response starts"; AWS says the same for an identical request sent before the first has started its response. This is C51 (branch scheduling) and it is confirmed by both vendors.
- Rate limits: cache reads are not deducted from Anthropic's input rate limit (the 1-hour section of the caching page) and Bedrock's OpenAI rows say the same; C33 already relies on this.
- Anthropic automatic caching is "not available on Amazon Bedrock (`bedrock-runtime`)" per Anthropic's page, while AWS's page documents it for Converse through `additionalModelRequestFields` on nine named models. The two pages describe different Bedrock surfaces (the legacy runtime integration against the Converse path); C41 says "every platform except Anthropic's legacy Bedrock integration", which is consistent. Do not generalise either statement.
- Server tool results add an automatic 5-minute breakpoint even when every marker asks for 1 hour (tool-use-with-prompt-caching page). We use no server tools on Anthropic today, so this is a note for Z5.

## 4. The tool list (Track Z)

Facts (Anthropic tool search page and tool-use-with-prompt-caching page, 2026-11-11):

- `defer_loading: true` keeps a tool out of the context window "not what you send in the request": every definition is still sent on every request. Deferred tools "are not included in the system-prompt prefix"; a discovered tool is appended as a `tool_reference` in the conversation, so "the prefix is untouched, so prompt caching is preserved".
- A deferred tool cannot carry `cache_control` (400). The breakpoint goes on a non-deferred tool. At least one tool must be non-deferred; keep the 3 to 5 most used loaded.
- Limits: 10,000 deferred tools, 5 results by default (1 to 10,000 settable), regex pattern 200 characters, BM25 query 500. Anthropic: tool selection "degrades once you exceed 30 to 50 tools"; a five-server setup is about 55k tokens, "typically reduced by over 85 percent". When to use: 10 or more tools or over 10k tokens of definitions.
- Availability: Claude API, Bedrock, Claude Platform on AWS, Google Cloud, Foundry; on Bedrock "not available through the Converse API", only InvokeModel. Programmatic tool calling: Claude API, Claude Platform on AWS and Foundry; not Bedrock; not eligible for zero data retention.
- Tool-use overhead: when any tool is present the API adds a fixed system prompt, 286 tokens on the 5.5 models (406 for `any` or `tool` choice on Haiku 5.5). Anthropic's own computer-use toolset costs about 4,500 tokens and browser-use about 6,600 (pricing page).
- OpenAI `tool_search` and Claude Code's MCP tool search are covered, from secondary sources only, in `plans/tool-overhead.md` section 3; not re-read here.

Break-even for deferring (our client-side `search_tools`, which changes the tool list on activation) against caching the full list. Let T be the list size in tokens, k the tokens of the activated tools, n the requests remaining in the session, p the price ratios of Anthropic's 5-minute scheme (write 1.25, read 0.1, base 1). Keeping the full list cached costs T x 0.1 per request after the first write. Deferring leaves a core list of C tokens (C much smaller than T) and each activation rewrites the whole prefix once, costing (all tokens after the tools, S, plus C plus k) x 1.25 minus what a read would have cost. With S the size of the system and history at the time of activation, one activation costs about (S + C + k) x (1.25 - 0.1) = 1.15 (S + C + k), and saves (T - C - k) x 0.1 per request. Deferral wins when (T - C - k) x 0.1 x n_after > 1.15 (S + C + k) x a, where a is activations per session. With T = 8,800 (60 MCP tools plus built-ins, plans/tool-overhead.md), C = 2,700, k = 250 and S = 40,000 at the activation, the saving is 585 tokens-equivalent per request against 48,700 per activation: it takes 83 requests after one activation to pay back, and activations early (S small) are 10 times cheaper. The conclusion is not "never defer": it is that late activations cost more than the list does, so (a) activate in the first requests when S is small, (b) the `tool_reference` route that never touches the prefix (provider-native search, or Z3's stable `call_tool`) is the only one that is safe at S = 40,000, and (c) on a model with no cache (local servers) T is paid in time, not money, on every request, and deferral wins at a much smaller T. Numbers are arithmetic on the repo's own measurements, not a live run (experiment E3).

## 5. Context management (Track V and C10)

Pending: Claude Code compaction, Aider repo map, Cline, context rot evidence, effective against advertised windows. Server-side facts already read:

- Context editing (https://platform.claude.com/docs/en/build-with-claude/context-editing, 2026-11-11): beta header `context-management-2025-06-27`; `clear_tool_uses_20250919` (defaults: trigger 100,000 input tokens, keep 3 tool uses, optional `clear_at_least`, `exclude_tools`, `clear_tool_inputs`) and `clear_thinking_20251015`. Listed on the Claude API, Bedrock, Bedrock runtime, Claude Platform on AWS, Google Cloud (Google managed) and Foundry. "Each clearing incurs cache write costs", which is why `clear_at_least` exists; this is the same economics as our batched masking (VA1: batch at a trigger, keep 3). `count_tokens` accepts `context_management` and reports `original_input_tokens`, so the saving can be previewed for free.
- Compaction (https://platform.claude.com/docs/en/build-with-claude/compaction, 2026-11-11): on demand (beta header `compact-2026-09-04`), at a token threshold, or your own summarizer. The overview says it keeps context small "because response quality degrades as a conversation grows". Platform support per mode is on sub-pages not yet read (unverified for Bedrock).
- Long context pricing (pricing page): Claude 4.6 and later (except Haiku 5.5) include the full 1M window at standard pricing; Haiku 5.5 is priced by prompt length with a tier above 100,000 tokens, counting cache reads and writes, each request priced on its own. Our `findModelPricing` applies exactly this (`calculateRequestCost.ts` Haiku 5.5 entry).
