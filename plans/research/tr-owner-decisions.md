# Track TR: the nine owner decisions

Decision memo, 2026-11-11, from [`tool-exposure-roles-prompts.md`](./tool-exposure-roles-prompts.md) (evidence and URLs are there). Nothing is built; no model call was made. Each row says what I recommend, why, and what you give up. Rows are the Open decisions in `plans/ROADMAP.md`.

| #   | Decision (row)                                           | Recommend                                                                                                                                                   | Why (evidence)                                                                                                                                                                                                                                                                                                                          | What you give up                                                                                               | Effort, risk |
| --- | -------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- | ------------ |
| 1   | Plan mode and MCP (TR2)                                  | Only user-trusted read-only MCP tools, or tools the user lists for Plan                                                                                     | The MCP spec says tool annotations are untrusted unless the server is trusted. The CLI believes any server's hint today; the IDE offers every MCP tool in Plan. Claude Code is looser (subagents keep MCP tools), Cline Plan blocks edits and commands.                                                                                 | Plan loses MCP tools without a trusted read-only hint (for example a docs search) until the user lists them.   | S, low       |
| 2   | Mid-session MCP toggles (TR3)                            | Apply at the next request and say in the UI that it costs one cache miss                                                                                    | Anthropic: changing tool definitions invalidates the whole cache; Claude Code also re-reads on `list_changed`. Waiting for the next session makes the toggle useless for the case it exists for (turning off a noisy or suspect tool).                                                                                                  | One uncached re-read of the conversation per toggle, bigger on long sessions.                                  | M, low       |
| 3   | MCP tools in unattended and background runs (TR1, TR3)   | None unless the user lists the tools                                                                                                                        | Nobody is there to approve; injection through tool results is the main risk and Haiku 5.5 and Gemini CLI both treat tool output as untrusted data. Claude Code inherits MCP into background subagents, so this is a deliberate difference.                                                                                              | A Loop or background run cannot use a configured MCP server until you list it; one extra setup step.           | S, low       |
| 4   | New tools from a changed MCP server (TR4)                | Hidden from the request until approved                                                                                                                      | "Rug pull": a server can change a description after approval (Invariant Labs, 2025-04-01); the spec lets servers push `list_changed`. Pinning per tool (X1b) closes it only if new tools are held back.                                                                                                                                 | A prompt after every server update; users who like auto-updating servers will click through more.              | M, medium    |
| 5   | Reviewer tools and script excerpt (TR8)                  | No model-callable tools; add the 4 KB script excerpt with a detector hit forcing `ask`, behind a flag that stays off until the reviewer eval (M8) scores it | A reviewer with tools is an injection pivot and OpenAI, Anthropic and Gemini all say tool output is the attack surface. But it cannot judge a script it cannot see; the first reviewer runs showed 0 of 37 floor false allows on Haiku 4.5 and 2 of 37 on Nova 2 Lite (B52), so the excerpt is the lever worth measuring.               | Until M8 runs, the reviewer sees the command only, so script contents stay a known blind spot (today's state). | M, medium    |
| 6   | Orchestrator and background as model uses (TR13)         | Keep them modes of `agent` and `loop` for now; revisit when a run needs a different model                                                                   | Roo's orchestrator is a mode with no tool groups, Claude Code subagents pick a model per definition (default: inherit). No evidence yet that we need a separate model setting; Anthropic warns subagent cost can dominate a session, so a default of "inherit" is safe.                                                                 | No `modeModels.orchestrator` or `background` yet; one model per run.                                           | none         |
| 7   | Mode text in the system prompt or a first message (TR10) | Leave it until K18 slice 2                                                                                                                                  | A plan to agent switch changes the tool list as well, and tools come first in the cache prefix (`plans/tool-overhead.md`), so moving the mode text alone saves nothing in that case. Newer Claude models also reject changed system text under preserved thinking, which argues for deciding once, with the rest of the prompt changes. | The cache win stays unclaimed; no byte change for users now.                                                   | none         |
| 8   | One tagged format for rules in IDE and CLI (TR10)        | Yes, one tagged form, shipped in the same release as the other prompt-text changes (rank 7 in section 10)                                                   | Anthropic recommends XML tags for mixed content; Google says either but be consistent; OpenAI's own prompts use tag-like blocks. No source shows a quality gap, so the argument is one cache prefix and one thing to test, not accuracy.                                                                                                | Every user's bytes change once (one cache miss on first request after upgrade); do it with other text changes. | M, medium    |
| 9   | Hosted-model spend for confirmation runs (TR12)          | Approve a capped amount after the free lab results, for example up to USD 30 for the tool-count sweep (E2) and the role test (E3) on one Sonnet-class model | The vendor thresholds (20, 30 to 50 tools) are for their models, not ours; a confirmation on one hosted model is cheap. Estimate: 540 runs of about 15k input tokens is about 8 million input tokens, about USD 24 uncached at an assumed USD 3 per million; confirm the price before approving.                                        | Spend; and one hosted family does not stand for all.                                                           | S, low       |

Order I would decide in: 1, 3 and 4 together (they are one story, MCP trust), then 2, 5, 8 and 9. Rows 6 and 7 can stay as written.

What would change my mind: for 1, a trusted read-only hint on most of your own servers (then no real loss); for 4, if updates are frequent and approval fatigue shows up in use (then approve per server, hide only tools whose hash changed); for 5, if the first reviewer eval already passes with the command alone; for 9, a lab result showing no tool-count effect on our families (then skip the hosted run).
