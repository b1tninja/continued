### 2.2 Findings that change what we do

1. **Anthropic's list endpoint is now a capability database.** `lifecycle`, `retires_at`, `max_input_tokens`, `max_tokens` and an `effort` and `thinking.types` object per model. `fetchModels.ts` already uses four of those fields and the comment says `lifecycle` "is only returned by newer API versions" while sending `anthropic-version: 2023-06-01`. The same page's example uses `anthropic-version: 2026-10-21`. Recommendation: send the newer version on the listing call only (the listing is read-only) and read `capabilities.effort` to generate the reasoning variants of the catalog (today variants come from the server only for llama.cpp and Strata).
2. **A sampling-parameter break is scheduled in the API itself.** The deprecations page says `temperature`, `top_p` and `top_k` are "removed in API version `2026-10-21`" and return 400, and that earlier versions already return 400 for non-default values on Claude 4.7 and later and Mythos Preview. `core/llm/llms/Anthropic.ts` builds `temperature`/`top_p`/`top_k` from options and only strips them when thinking is on (`anthropicSamplingParams`). Today's header `2023-06-01` keeps it working for older models, but a user with `temperature` set on a 4.7+ model gets a 400 now. Row proposed below (a pinned per-model "no sampling" fact, then a test).
3. **Retirement is close for two models in the product's own table.** `claude-sonnet-4-5-20250929` retires 2026-11-30; `claude-opus-4-5-20251101` "not sooner than" 2026-11-24; `claude-haiku-4-5-20251001` "not sooner than" 2026-10-15 (already past). Anthropic promises at least 60 days of notice and states that Bedrock and Google-managed Vertex set their own schedules, so a deprecation on one route says nothing about the others. This is exactly what `routes` in the catalog can exploit.
4. **Bedrock: the OpenAI-compatible endpoint moved.** AWS now serves Chat Completions and Responses on `bedrock-runtime` (`/openai/v1`) and tells new applications to prefer it over Mantle. Our `BedrockMantle.ts` targets Mantle only, and `plans/model-families-2026-11.md` already treats "Mantle only for Grok in-region". The catch: `bedrock-runtime` has no `/models`, so discovery must use `ListFoundationModels` plus `ListInferenceProfiles` (K3), and closed-weight OpenAI GPT models there need an inference profile id (`us.` or `global.`), never the foundation id. Row proposed.
5. **API keys on Bedrock are a first-class, lower-risk path than the AWS credential chain for the CLI:** short-term keys (up to 12 h, same Region only) can be minted by a token generator library and refreshed per request; long-term keys are IAM users and AWS warns "exploration only". The product should prefer the short-term refresh route in the setup flow and warn on a long-term key.
6. **OpenAI: Responses is the only path for the newest models' tool calling.** "GPT-6 Astra and GPT-6.1 Sol require the Responses API for tool calling", and from GPT-5.4 Chat Completions refuses tools with a reasoning effort other than `none`. Whether our OpenAI provider has a Responses path was not measured here; section 8 rank 9 is the check.
7. **No list endpoint carries prices** except OpenRouter. Anthropic, OpenAI, Gemini, Mistral and DeepSeek lists carry limits and (Anthropic, Mistral, DeepSeek) capabilities, never prices. The price tables stay hand-kept or come from a third party (section 4).
8. **Ollama's `/api/show` is the only local fact source for the template and tool support,** and its `capabilities` list (completion, vision, and per the docs reviewed possibly tools and thinking) was not exhaustively documented on the page read; MR2 already plans this probe.

### 4.2 Design: a generated, reviewable catalog with provenance

Principles: the product never fetches at runtime for a price decision (this is already the `cost-counter.md` decision); a human reviews a diff; every cell names its source and date.

1. **Collectors (MR2, dev only).** One script per source writes `bench/research/out/<source>.json` outside any repository, with `fetchedAt`, the request, a hash of the body and the parsed rows. Anthropic, OpenRouter, Ollama `/api/show`, llama.cpp `/props`, Bedrock `ListFoundationModels` and `ListInferenceProfiles` (needs a key, so run by the owner), models.dev and LiteLLM.
2. **Merge with a precedence per field,** recorded in the output: limits and lifecycle from the vendor list; prices from the vendor page or the AWS file; capabilities from the vendor list, then models.dev, then LiteLLM; disagreement between two sources is not resolved, it is printed.
3. **`propose`** (MR13) writes a diff against `surfaceFacts.generated.json` and the price tables, each changed cell with `{value, source, url, fetchedAt, level}`. Levels reuse PL1's: `declared`, `derived`, `measured`. A models.dev or LiteLLM value is `declared` at best and cannot enable a feature by itself.
4. **Review gate.** Pull request with the diff, an offline schema test (no fact without level and date), and a `staleAfter` per row so an old row shows as stale rather than silently right.
5. **Deprecation watch.** A weekly human-started command reads only Anthropic `lifecycle`/`retires_at`, OpenAI `shutdown_date`, OpenRouter `expiration_date` and models.dev `status`, and lists models in a user's `config.yaml` that are within 60 days of retirement or already retired. This one is allowed to reach the product as a notice, because it is a warning about the user's own configuration, not an auto-written table.

Cost: the collectors are about one day each; the merge and `propose` about three days; the watch about two. No paid calls except Bedrock listing (free) and a provider key for listing.

### 5.2 What the best UX looks like, from the above

1. **One model by default, a switch for two.** Cline's toggle and Claude Code's `opusplan` both start from a single model. Nobody ships seven pickers up front.
2. **Name roles, not providers** (our plan's own lesson from Cline's shared endpoint fields): a role holds a model, and the model carries its account.
3. **Say what a switch costs.** Claude Code documents the uncached re-read after a model change; ours already has cache warnings that count a route change as a model change (`model-catalog.mdx`). Surface the estimate in the picker, not only after the fact.
4. **Show what was used.** The reported Cline failures are all "the setting did not take effect". A line per turn naming the model and effort actually used is the cheapest defence (our M7).
5. **Memory is per task, not only per mode.** Roo keeps the profile a task started with, even if the global selection changes. That prevents a mid-task switch from silently changing the cache and the cost.
6. **A utility model is a first-class slot** (VS Code, Zed, Kilo, Aider's weak model): summaries, titles and commit text do not need the agent's model.
7. **Warn on a setting that is ignored** (our M8): Cline's silent fallback and Claude's sampling-parameter 400 are the same class.

## 7. Risks

1. **A third-party catalog becomes a source of truth by accident.** models.dev and LiteLLM are community assertions. Mitigation: they may only produce `declared` facts, a diff names the source, and no fact below the evidence floor enables a feature (PL1's rule).
2. **A generated catalog goes stale silently.** Mitigation: `staleAfter` on every row and a weekly human-started check; no runtime fetch for money decisions (the `cost-counter.md` rule).
3. **The Anthropic version bump.** Moving the Messages call to `anthropic-version: 2026-10-21` removes `temperature`, `top_p` and `top_k` (400). Do not bump the version on the Messages path without the sampling guard; the listing call may use the new version safely.
4. **Retirement of models users have configured.** `claude-sonnet-4-5-20250929` retires 2026-11-30; Bedrock and Vertex follow their own schedules, so a fallback route may outlive the model.
5. **Importer reads secrets by mistake.** Each new adapter is a new place to leak. Mitigation: the existing rules, plus a fixture per adapter that contains fake secrets and a test that none reaches the preview.
6. **File formats move.** Windsurf's docs now live under `docs.devin.ai` with `.devin/` paths; Cursor and Codex docs redirected to new hosts this year. Every adapter row carries a `readOn` date and a contract test.
7. **Local-server facts differ by build.** `/api/show`, `/props` and `/slots` fields vary by version (MR27 already records a llama-server build with no `Chat format` line). Use fingerprints, not names.
8. **Pages summarised by a fetch tool can be wrong.** Field names in this document marked "not read" were not seen on a primary page. Verify before coding against them.
9. **Docs links older than six months in our own tables.** The Azure page read has `ms.date` 2026-05-13 (just over six months). Seven files in `docs` and `core/llm` still cite `ai.google.dev` or `docs.anthropic.com`, both of which now answer 301.
