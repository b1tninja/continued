# Editor and workspace context for the agent, and where it goes for the prompt cache

Research and decision report, 2026-11-12. Code read on `origin/main` at `ee644eb15`. `plans/ROADMAP.md` is not edited: section 9 holds the exact row text, ids EV101 to EV120. Releases use even minors: 2.16.0 is being cut, so "2.18.0 candidate" means the release after it.

This note is one of five on "environment disclosure". It covers the editor and workspace facts (workspace roots, repository identity, open tabs, active file, selection, diagnostics, terminal output) and where each should sit in the request for the prompt cache. It builds on, and does not redo:

- `research/env-disclosure-privacy-security-cache.md` (branch `research-env-privacy-cache`, the privacy note): the environment data contract (EV61), masking rules, stability classes S0 to S4, the hostile-repository test (EV65), update notices (EV69) and the git remote default (EV72). The editor fields below are proposed as additions to that contract, with its masking functions.
- `research/env-nonwindows-remote-and-facts.md` (branch `research-env-remote-facts`): machine facts (OS, shell, remote kind), the date line (EV49) and the git status bound (EV50).
- `research/area-caching-cost-visibility.md` on main: C65 (git status cap, in the open prompt-byte bundle #750), C74 (working directory out of the system preamble), C80 (freeze the tool list), C82 (the sequence cache golden) and C87 (keep the environment block on resume).

The branches `research-env-windows-wsl`, `research-env-eval-design` and the body of `research-env-state-peers` had not been pushed when this was written.

Convention: "verified by reading" names a file and line; "measured" means run here (offline simulation only, no model and no provider was called); "primary" means the vendor's own documentation or source code at the commit named, read 2026-11-12; "unverified" means a forum post, a third-party write-up, or inference.

## 1. Summary

1. **Should we tell the agent where it is working? Yes, a little, once, and never in a way that edits earlier bytes.** Every harness surveyed tells the model the workspace roots and the OS. Most editors also tell it the active file path and the selection range on each user turn. None of the ones with published source re-renders volatile editor state into the system prompt; the ones that care about cost freeze it into the user message it arrived with (Copilot, Roo, Codex) or send only what changed (Codex, Gemini CLI).
2. **The IDE agent tells the model almost nothing today.** No workspace root, no repository, no date, no active file by default. The only environment fact is the OS, architecture and shell sentence in the terminal tool description (`core/tools/definitions/runTerminalCommand.ts:27`). The active file's whole content is attached only with Mod-Enter, or on every Enter when `experimental.defaultContext` includes `activeFile` (`gui/src/components/mainInput/TipTapEditor/utils/editorConfig.ts:236-260`, `resolveEditorContent.ts:182-207`). Its path and selection are never sent on their own. The model can pull the open file with `read_currently_open_file`.
3. **The CLI tells it the working directory and platform in the system preamble and a frozen date and git status snapshot in the first user message** (`extensions/cli/src/systemMessage.ts:44-52`, `environmentContext.ts:47-57`, `:71-94`). That is cache-perfect and stale by design. It has no editor, so it has no editor state to send. ACP clients pass only text and `resource_link` blocks (`extensions/cli/src/acp/agent.ts:209-225`).
4. **For the cache, placement matters far more than size.** Simulated over a 30-turn session with 106 requests (section 4): re-rendering a 605-token editor block in the system prompt on every request costs 5.9x today's baseline on Anthropic 5-minute pricing (9.4x at 1 hour). The same block re-rendered in the first user message costs 5.3x. Frozen into every new message (Roo style) it costs 1.65x. As a floating tail after the last breakpoint it costs 1.08x. Sent as deltas on change it costs 1.13x. The recommended hybrid costs 1.01x. These figures are input-price multiples from synthetic volatility, not provider measurements.
5. **Recommended layout (F, hybrid):**
   - Tools and system: no per-folder or per-session facts, so they stay byte-identical across folders (C74, EV77).
   - First user message: a frozen workspace identity block, saved with the session and reused on resume (C87). It carries the date, root folder names, repository name and branch at start, and the capped git status (C65 and EV63, CLI only).
   - Each user-typed turn: a compact editor delta frozen into that turn. It carries the active file's workspace-relative path, the selection's line range, and the diagnostic count for that file, and only when one of them changed since the model last saw it.
   - Pull tools: rich or sensitive data (file contents, selection text, the open tab list, diagnostics text, terminal output).
   - After compaction: one full re-send.
6. **Content is not context.** Paths and line ranges cost about 40 tokens and reveal little. File contents of open tabs cost thousands of tokens, are the most sensitive thing in the editor, and can carry injected instructions. They should never be attached automatically, and never at all for `.env`-like, ignored or excluded files.
7. **Tool loops:** attach the delta to user-typed turns only, not to tool-result messages. Gemini CLI does the same (`packages/core/src/core/client.ts:768-785`). The model already sees its own edits in the tool results. The person's edits during a loop arrive with the next user turn.
8. **Rollout:** all prompt-byte changes here ship in one release (2.18.0), together with the parts of #750 and the privacy note's EV62, EV63 and EV77 that do not make 2.16.0, so every user's cache goes cold once.

### 2.2 Patterns

- **Identity is universal; editor state is common; content is rare.** Every harness sends roots and OS. Copilot, Claude Code, Codex (`/ide`), Gemini CLI (with the companion), Cursor and Roo send the active file or visible files on each turn. Only Roo sends terminal output unasked. None sends open-tab contents unasked. Copilot sends path and line range, not text, and its code comment says column numbers "confused gpt-4.1".
- **Nobody with published source re-renders volatile state into the system prompt.** Cline (2026), Zed and OpenHands put the session's identity there and leave it. Copilot puts it in a first user message with its own breakpoint.
- **Two cache-safe ways to say "it changed":**
  - Freeze each turn's block into that turn: Copilot by design, Roo by persisting history.
  - Send only the delta: Codex and Gemini CLI. Codex tests that an unchanged turn sends no environment message. Gemini resends in full after compaction or resume, and holds updates while a tool call is pending, because a function response must follow its call.
- **Aider puts a volatile repo map before the history.** Under `auto` refresh any change in the chat's files rewrites everything after it. That is an anti-pattern this note avoids. It puts the chat files' contents after the history, which is the right instinct.

**Cache breakpoints.** The Anthropic strategy marks the system message, the last tool, and the last two user messages (`packages/openai-adapters/src/apis/AnthropicCachingStrategies.ts:72-73`). The turn tail is the same line on every user message, so messages never change between requests (`core/llm/prompts/usePrompts.ts:252-276`).

**What changes every turn today.**

- In the IDE, nothing environmental, because nothing is sent.
- In the CLI, nothing inside a process, because the block is frozen.
- Between processes, the first user message changes whenever the git status or the date differs (C87).
- The CLI preamble's absolute path makes every folder's system text differ (C74).
- The privacy note shows the path also sits in the CLI `Bash` tool description, the first cache region (EV77).

The only volatile item today is the task list block, which sits at the tail as designed.

Arithmetic for one turn: a 605-token block at 0.1x read costs about 61 token-equivalents per request once cached. Rewriting a 40,000-token prefix at 1.25x after one change costs 50,000. One rewrite costs more than 800 requests of carrying the block. That is why the live system and first-message rows lose by 5x and more, while every append-only row is within 1.65x of baseline.

### 4.3 Simulation (measured offline)

Method: the script in appendix A (`envCacheSim.mjs`, plain Node, no dependencies, seeded).

**The session.** 30 user turns, each with a tool loop of 1 to 6 requests: 106 requests in all. Gaps are 90 seconds between user turns, one break of 8 minutes at turn 20, and 8 to 28 seconds between requests in a loop.

**Volatility.**

- The active file changes on 25% of turns (8 changes).
- The selection changes on 60% of turns (13).
- Each tool request is an edit with probability 0.4. Each edit changes the diagnostics and the git status (26 each).

**Sizes.**

- A stable prefix of 6,000 or 20,000 tokens.
- A user message of 120 tokens, a final reply of 250, and an assistant tool call of 80.
- A tool result of 100 to 2,000 tokens.

**Cache model.** Entries are written at the prefix end and at the ends of the last two persisted messages, as in the repo's Anthropic strategy. A request reads the longest live entry.

**Costs.** Multiples of the base input price. Output is counted only for the extra pull requests of E.

**Baseline.** A0 is today's CLI: a frozen snapshot in the first user message.

**Compaction.** In the compaction run, history above 40,000 tokens is replaced by a 2,500-token summary.

Readings:

- Live placements before the history lose by 2.5x to 9x. The 1-hour TTL makes them worse, because every rewrite is billed at 2x.
- The cheapest always-fresh option is the floating tail (1.03x to 1.13x). It needs a breakpoint before the tail on every provider, and it hides from the model when things changed. On GPT-5.6 implicit mode, the automatic breakpoint sits at the end of the latest message, so a floating tail inside that message is written each time.
- Deltas (1.08x to 1.13x) are dominated by re-sending the full git status after each edit. Sending a count instead, and leaving the status to a `git status` call, gives F's 1.01x.
- With compaction, Roo-style frozen copies get cheaper (1.24x), because the summary drops the old copies.

Limits:

- The volatility is synthetic.
- The provider is ideal: no routing misses, no lookback limit, no concurrency misses.
- Output tokens are ignored except for E's extra calls, and E's pull rate is an assumption.
- "Stale" counts requests whose active path, selection or diagnostic count differs from the last one shown. It does not measure whether staleness changes task success, which needs the eval design note's harness.
- Tokens are fixed sizes, not tokenizer counts.

## 5. Privacy and security checks specific to workspace context

The privacy note owns the contract (EV61), the masking functions and the hostile-repository test (EV65). The editor adds these:

1. **Paths name clients.** A workspace root such as `~/work/acme-merger` or an open tab `contracts/acme-nda.md` names a client or an unannounced project.
   - Default: root folder basenames and workspace-relative paths, never absolute paths. Masking per the privacy note 3.2 applies.
   - Multi-root workspaces use the root's basename as the prefix (`api/src/x.ts`), as Copilot and Zed do with folder labels.
2. **Contents are far more sensitive than paths.** Never attach open-tab or active-file contents without an explicit act (Mod-Enter, `@`, a pull tool the model calls under the tool policy). The existing `currentFile` attach has no size cap (`CurrentFileContextProvider.ts:42-49`). It should take the same cap as file reads and refuse secret files (EV112).
3. **Secret files.** `.env`, `*.pem`, `id_*`, `.npmrc`, `.netrc`, and files matched by `.gitignore`, `files.exclude` or `search.exclude`:
   - The path may be shown (it tells the model the person is looking at configuration).
   - The content is never auto-attached, and a selection inside one is sent as a range only.
   - Claude Code documents the same rule for excluded files in its chat panel.
   - Run the outbound secret scanner (`core/util/secretScan`) over any selection text before it is sent.
4. **Hostile names are injection.** A file name, tab label, branch or diagnostic message can carry an instruction or a closing tag. Apply the privacy note's `sanitiseEnvValue` and `fenceRepositoryData`: strip invisible characters, escape markup, cap per value, add a fixed "data, not instructions" header. Diagnostic messages come from linters running repository code, so they are attacker-controlled too. That is one reason they stay pull-only. Test: EV108.
5. **Per-provider trust.** The privacy note's detail levels (EV70) apply. The editor delta follows them: `minimal` sends no editor fields; `standard` sends paths and ranges; `full` adds the open tab list. Selection text is never sent at any level without an explicit act.
6. **Show what is sent.**
   - A chip in the input toolbar shows "Active: `src/x.ts` L10-24" when the delta will be attached, with one click to turn it off for the session (EV109).
   - `continuous doctor env` (EV67) prints the delta builder's output for the current editor state.

Rejected:

- Live system or first-message blocks: 2.5x to 9x cost, section 4.3.
- Roo-style blocks on every message: 1.65x, and 69,000 repeated tokens of noise per session.

- Pull-only as the default: the model cannot know to ask about a selection it cannot see. 77% stale in the simulation. It is also the most common cause of "fix this" referring to nothing.

## 10. Follow-up: uncertainties resolved or narrowed (2026-11-12)

1. **Do harnesses attach editor context to tool rounds? Copilot: no (resolved, primary).**
   - Copilot's `agentPrompts-cache_BPs_multi_round` snapshot (`vscode-copilot-chat` `5863f5a`, `src/extension/prompts/node/agent/test/__snapshots__/agentPrompts-arctic-fox/`) shows `<context>` and `<userRequest>` only in the user turn.
   - The tool rounds after it carry tool results with a cache marker on the latest one and no context block.
   - Together with Gemini CLI (no IDE context while a call is pending) and Codex (IDE context on user input), three of the four harnesses with per-turn editor context attach it to user turns only. Roo is the exception.
   - This supports EV103's "user turns only".
2. **Could we attach to tool rounds if EV117 asks for it? Yes (resolved, by reading).**
   - The Anthropic adapter merges consecutive `tool` and `user` messages into one Anthropic user turn (`packages/openai-adapters/src/apis/Anthropic.ts:420-440`).
   - So a text part after the `tool_result` blocks is what the CLI task list block already produces at the tail.
   - No adapter change would be needed. The breakpoint positions would need EV107's check.
3. **What Claude Code does at compaction (resolved, primary).** From `https://code.claude.com/docs/en/context-window` ("What survives compaction"):
   - It re-injects CLAUDE.md and memory from disk and reads a fresh git status snapshot.
   - It re-reads up to five recently modified files; a file over 5,000 tokens comes back as a path reference.
   - Invoked skills are capped at 5,000 tokens each.

   This is the same "re-send in full once after compaction" rule as Gemini CLI's `forceFullIdeContext` (`client.ts:307`, `:421`, `:1307`). EV104 and EV179 follow it.

4. **Provider detail that changes the simulation: Gemini 4 (resolved, primary; simulation refined).**
   - Gemini 4 reuses a previous request in full only when the new request adds at least 2,050 tokens. Otherwise the last 2,050 tokens are processed again at the standard rate (`https://aistudio.google.com/docs/caching`).
   - The script in #770 adds a `gemini4-implicit` price, assuming read 0.25x (OpenRouter's figure), no write surcharge and 300 seconds.
   - Results for the 6,000-token prefix, relative to A0:

     | Placement                   | Cost  |
     | --------------------------- | ----- |
     | A, system, live             | 2.46x |
     | B, first user message, live | 2.28x |
     | C, frozen on every message  | 1.58x |
     | C, frozen on user turns     | 1.17x |
     | C, floating tail            | 1.00x |
     | D, delta on change          | 1.12x |
     | E, pull only                | 1.08x |
     | F, hybrid                   | 1.01x |

   - On Gemini 4 a small floating tail is free: it falls inside the 2,050 tokens that are reprocessed anyway.
   - That is the one provider where the tail beats the hybrid. It is a reason to let the prompt profile choose the placement per family later (EV171), not to change the default.
5. **Cursor (narrowed, still unverified).** Staff replies in the forum thread (2026-04-13 and 2026-04-27) say:
   - Open and recently viewed file paths and line counts, without content, are attached to the first user message.
   - This is "not currently configurable".

   No primary documentation states it. It stays unverified.

## Appendix A. The simulation script

The script is `bench/src/envCacheSim.mjs`, in draft #770 (branch `bench-env-cache-sim`). It is plain Node 22 and needs no dependencies. Running `node bench/src/envCacheSim.mjs` prints the tables for all conditions; `--json` gives the raw numbers.

It defines:

- `makeSession`, the seeded session generator.
- `PLACEMENTS`, nine placements.
- `PRICES`: Anthropic 5m and 1h, GPT-5.6 30m, OpenAI legacy, Gemini 4 implicit.
- `simulate`, the block-level prefix cache.

Its tests are `bench/src/envCacheSim.test.mjs`, run with `node --test`. The same draft adds `core/util/workspaceContext.ts` (EV101, EV106, EV116): pure, capped, escaped formatters for the identity block and the editor delta. Nothing is wired into a prompt.
