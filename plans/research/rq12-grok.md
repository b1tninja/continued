# RQ12: Grok (xAI), the raw tool-call form and `tool_choice` on Mantle

Desk research, no model call, no parser. Everything below was fetched 2026-11-11. The short answer: **nothing public** describes the raw tool-call text of any current Grok model, and the one released weights set with a post-trained chat format (Grok-2) has a template with no tool section. `tool_choice` on xAI's own API is documented; on the Mantle route it is **not documented by AWS and not tested by anyone we could find**.

## Is there a public chat template or tokenizer for the raw tool-call form?

**Nothing public for the raw form.** What exists:

| What                                | Where                                                                                                                                                     | Says about tools                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| xAI function-calling guide          | https://docs.x.ai/docs/guides/function-calling (fetched 2026-11-11)                                                                                       | Describes only the envelope: tools as `{"type": "function", name, description, parameters}`, a `function_call` item with `name`, `arguments` and `call_id`, results as a `function_call_output`; "with streaming, the function call is returned in whole in a single chunk". No special tokens, no template, no text form. A schema that "cannot be compiled into a tool-call grammar" is rejected with a 400, which suggests the call is produced under server-side constrained decoding, so there may be no free-text form to recover at all. That is an inference from one error sentence, not a statement in the docs. |
| Grok-1 weights                      | https://huggingface.co/xai-org/grok-1 (Apache-2.0, created 2024-03-17)                                                                                    | A JAX checkpoint (`ckpt-0/tensor*`) and a README. Base model: no chat template, no tool format. The tokenizer there is not a Hugging Face one; `Xenova/grok-1-tokenizer` is a third-party conversion.                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Grok-2 weights                      | https://huggingface.co/xai-org/grok-2 (Grok 2 Community License, created 2025-08-22)                                                                      | Files: `config.json`, `tokenizer.tok.json`, `LICENSE`, `README.md` and sharded `pytorch_model-*.safetensors`. **No `tokenizer_config.json`, no `chat_template.jinja`.** The README says "This is a post-trained model, so please use the correct chat template" and links SGLang's `tiktoken_tokenizer.py` (commit `97a38ee`).                                                                                                                                                                                                                                                                                             |
| The Grok-2 chat template, in SGLang | https://raw.githubusercontent.com/sgl-project/sglang/97a38ee85ba62e268bde6388f1bf8edfe2ca9d76/python/sglang/srt/tokenizer/tiktoken_tokenizer.py, line 106 | `Human: ` + user text + `<\|separator\|>\n\n`; `System: ` for system; `Assistant: ` for assistant; generation prompt `Assistant:`. Roles `user`, `system` and `assistant` only: no `tool` role, no `tool_calls` branch, and `apply_chat_template(..., tools=None)` accepts `tools` and ignores it.                                                                                                                                                                                                                                                                                                                         |

| Third-party conversions             | `unsloth/grok-2-GGUF`, `bartowski/xai-org_grok-2-GGUF`, `DevQuasar/xai-org.grok-2-GGUF` on Hugging Face                                                   | Quantised copies of Grok-2; not primary sources and not read for a template.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| Other `xai-org` repositories        | Hugging Face API, author `xai-org`, listed 2026-11-11                                                                                                     | Only `grok-1` and `grok-2`. No weights or tokenizer for Grok 3, 4, 4.3, 4.6 or 4.7 are published under that account.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |

So the answer for the model we would actually call (Grok 4.x on Bedrock) is: **nothing public**. There is no template, no tool-call tokens and no tokenizer. Grok-2's published format has no tool form, so it cannot stand in for it. A parser written for Grok today would be a guess, and none is proposed. The preset table's `grok` row already says "raw format undocumented" and `textDialect: "none"`; that stays true.

No corpus fixture was added for Grok, for the same reason.

## `tool_choice` on the Mantle route

| Source                                                                                                                                        | What it says                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| --------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| xAI function-calling guide (https://docs.x.ai/docs/guides/function-calling)                                                                   | `tool_choice` takes `"auto"` (default), `"required"`, `"none"` and a forced function `{"type": "function", "function": {"name": "..."}}`. Parallel calls are on by default, `parallel_tool_calls: false` turns them off. Every example uses `grok-4.7`; the page does not say which models support which value. This is xAI's own API, not Mantle.                                                                                                                                |
| AWS model card for Grok 4.6 (https://docs.aws.eu/bedrock/latest/userguide/model-card-xai-grok-4-6.html)                                       | On `bedrock-mantle` "client-side tool calling" is listed as supported; on `bedrock-runtime` server-side tool use is not. The model ids are `xai.grok-4.6` (Mantle) and `us.xai.grok-4.6` or `global.xai.grok-4.6` (`bedrock-runtime`, Converse and the OpenAI path), the path prefix is `/openai/v1`, and the Responses and Chat Completions APIs are both shown. The card does **not mention `tool_choice` or parallel tool calls** and lists no unsupported request parameters. |
| AWS launch post (https://aws.amazon.com/blogs/machine-learning/introducing-grok-on-amazon-bedrock/, seen through a search result only)        | Grok 4.3 on Mantle with OpenAI-compatible APIs; tool calling listed among the features. Not read in full.                                                                                                                                                                                                                                                                                                                                                                         |
| A third-party catalogue (Bifrost, `getmaxim.ai/bifrost/model-library/compare/bedrock_mantle/xai.grok-4.3`, seen through a search result only) | Lists "Tool Choice: Yes" for `xai.grok-4.3` on Mantle. A catalogue's claim, not AWS's, and not a test.                                                                                                                                                                                                                                                                                                                                                                            |
| Classmethod write-up (https://dev.classmethod.jp/en/articles/grok-4-6-amazon-bedrock-mantle-iam/)                                             | Tested text and image requests on Mantle with Chat Completions and Responses; no tool call, no `tool_choice`. Also found `bedrock-runtime` Converse failing with an invalid model id for the plain id.                                                                                                                                                                                                                                                                            |

So: **documented for xAI's API, undocumented and untested for Mantle.** Whether a given value is accepted, ignored or honoured on Mantle is unknown; "accepted" would still not mean "honoured" (`plans/forced-turns-and-grammar.md` keeps `toolForce` separate from `toolChoice` for that reason). Our Bedrock builders send `toolChoice: {auto: {}}` whenever tools are present, which is the Converse field and not the Mantle one.

## What would settle it (needs the quota, so not done)

The probe is cheap: one Chat Completions request to `https://bedrock-mantle.<region>.api.aws/openai/v1` for `xai.grok-4.6` with two tools and a no-tool prompt, once each with `tool_choice` `auto`, `required`, `none` and a forced function, counting HTTP status, whether a tool call came back and whether the forced name matches. That is the "Mantle `tool_choice` test" already named in `plans/forced-turns-and-grammar.md`. It waits on the Grok dollar quota (ROADMAP Q5, which is not requested because AWS accepts only a value above the 10M default).
