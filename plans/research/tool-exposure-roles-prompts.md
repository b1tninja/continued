# Tool exposure, roles, system prompts and prompt dialects: research and recommendations

Status: draft 2, 2026-11-11, written against `origin/main` 0d4fe36f3. Docs only: nothing here is built, no model call was made, and no number below was measured by us unless it says so. Roadmap: Track TR (rows TR1 to TR13), Track Z (the cost of the tool list), K18, K19, C62, PL1 to PL7, X1b. The owner's one-page memo is [`tr-owner-decisions.md`](./tr-owner-decisions.md). Every URL was fetched on 2026-11-11 unless a line says otherwise; a source older than six months (before 2026-05-11) is marked **[old]**.

## 1. Summary

1. **Role gating is a hard filter, not a prompt.** Every serious harness with per-role tools (Claude Code subagents, Roo modes, Cline Plan/Act) filters the list the model is offered and also refuses the call at execution. Our TR1 does both; keep it as the first row built.
2. **The tool count evidence is consistent in direction and soft in number.** Anthropic says selection degrades past 30 to 50 tools; OpenAI says fewer than 20 per turn, "a soft guideline". Our built-in lists are 10 to 17 tools (2,000 to 4,000 tokens); the risk is MCP, at about 100 to 125 tokens a tool in our fixtures and far more for real servers.
3. **Restricting without rewriting the prefix is possible on OpenAI (`allowed_tools`) and not on Anthropic.** A per-role list costs one cache prefix per role on Anthropic; roles are separate requests, so that is acceptable, and it is why a mid-session toggle must be priced in the UI (decision 2).
4. **Claude 4.5 to 5.x guidance says: plainer, no shouting, state the reason.** Aggressive "CRITICAL: You MUST" language now over-triggers tools; instruction piles from older models raise cost; "never" is read as absolute. Our turn text already has this shape; the cuts are in section 3.4.
5. **Dialect (XML, Markdown, JSON) matters less for Claude, Gemini and GPT than the vendor tool template matters for Qwen, Hermes and Llama.** Claude: XML tags for mixed content. Gemini: either, one style per prompt. GPT: Markdown headings, with tag-like blocks in its own examples. Open models: use the tool format the template was trained on. Evidence for "family X likes format Y" beyond vendor statements is thin, and we say where.
6. **MCP descriptions are untrusted input.** Gemini CLI wraps external tool output in `<untrusted_context>` and tells the model to treat it as data; Claude Code warns on MCP output over 10,000 tokens and saves text over 50,000 characters to a file. We have pinning (X1b); TR4 and TR5 add hide-until-approved, size caps and uri-keyed permissions.
7. **Skills: about 100 tokens of metadata each at start, body loaded on demand, under 5,000 tokens, SKILL.md under 500 lines.** That is the cheapest delivery for anything not needed every turn; rules that apply every turn belong inline; glob-scoped rules appended on first match are a cache break today (TR10).

### 3.3 Length against quality: what is evidenced

- Anthropic's recent guides report effects of specific added paragraphs with numbers (finish-the-task paragraph: about half as many unfinished sessions at +30 percent output tokens; an ownership sentence: consolidation from under 10 to about 75 percent of runs at +70 to 80 percent output tokens; a longer cost-stating subagent description: about half the subagent starts). None reports a length-quality curve for a whole prompt. Read: each paragraph should earn its place with a named behaviour and a measured cost.
- Haiku 5.5 guide: a long coding-agent prompt at low effort is where early stopping appears; a short prompt rarely stops early. One vendor datum on one model.
- Our own measurements (recorded in comments in `core/llm/prompts/turns.ts`): on Qwen3, short turns won or tied; Qwen3-Coder-30B with the full plan turn took 22 requests with 7 leaked calls against 10 and none with short. Lab evidence, small samples.
- Gemini CLI and Codex general prompts are long. No source we found ties their length to a measured gain.

### 5.2 Strategies, and what each costs

| Strategy                                 | How it works                                                                                                        | Cache effect                                         | Who does it                                                                                                  | Ours                                                   |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------ |
| Fixed set per mode or role               | The harness sends one list per mode                                                                                 | One prefix per mode; a switch is a miss              | Roo (groups), Cline (Plan blocks edits), Claude Code (Plan and Explore subagents)                            | Partly: IDE Plan drops edit tools; no role table (TR1) |
| Allowlist or denylist per tool or server | User or admin lists tools; deny wins                                                                                | A change is a miss                                   | Claude Code (`tools`, `disallowedTools`, `mcp__server__*`), Cursor (per-tool toggles), Roo (`excludedTools`) | Permissions yes; per-tool exposure no (TR3)            |
| Deferred loading, provider-side          | Send all definitions, mark most `defer_loading`; the model searches, results arrive as `tool_reference` in messages | Cache preserved; definitions still sent each request | Anthropic (not Bedrock Converse), OpenAI `tool_search` (gpt-5.4 or later)                                    | Not built (Z5)                                         |
| Deferred loading, client-side            | A `search_tools` meta-tool returns names; activated tools are appended to the list                                  | Activation rewrites the prefix once                  | Claude Code (on by default for MCP), us (off by default)                                                     | Built, off (Z1); activation miss unmeasured (Z4)       |
| Restrict by choice, not by list          | `allowed_tools` in `tool_choice` limits what may be called while the list stays                                     | Cache preserved (OpenAI docs)                        | OpenAI; Gemini has a similar `allowed_tools`                                                                 | Not built; a candidate preset fact                     |
| Executor refusal                         | The list may be wider than the role; the executor refuses calls outside the role's set                              | None                                                 | Roo (`isToolAllowedForMode`), our TR1                                                                        | TR1                                                    |

Reading: use the list filter as the primary control (it removes the temptation and the tokens), the executor refusal as the backstop (it covers text-recovered and history-replayed calls, which a list filter cannot), and `allowed_tools` only where a provider documents it and a measured need appears.

| Our `Skills` tool             | The tool description lists skill names                                                                                 | Names only, below the 100-token metadata; but the list sits in the tools region, so a new skill is a prefix break | `extensions/cli/src/tools/skills.ts`                  |

Rule of thumb for inline against on demand (a proposal, to be checked by experiment E5): inline when a rule is short (about 300 tokens or less in total across all inline rules) and applies to most turns; on demand when it is long, domain-specific or tied to a path. Deliver glob-scoped rules as text attached to the tool result of the read that matched, so the system prefix does not move (whether Claude Code does this is not verified; the idea is ours). Put the skill registry in the first user message, not in a tool description, so adding a skill never rewrites the tool prefix (C62 already names this offender).

## 8. MCP tool description hygiene

| Risk                                                                                          | Evidence                                                                                                                                                                                                                                      | What we should do                                                                                                                                                                  |
| --------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Hidden instructions in descriptions (tool poisoning), rug pulls, cross-server shadowing       | https://invariantlabs.ai/blog/mcp-security-notification-tool-poisoning-attacks (2025-04-01) **[old]**: a hidden "sidenote" argument exfiltrated `~/.ssh/id_rsa` and a config file in Cursor; a server can change a description after approval | Pin per tool and hash definitions (TR4); show the full description in the Tools page and approval (TR3); never let one server's text name another server's tools.                  |
| Annotations (`readOnlyHint`) can lie                                                          | MCP spec 2025-11-25: "clients MUST consider tool annotations to be untrusted unless they come from trusted servers" (https://modelcontextprotocol.io/specification/2025-11-25/server/tools)                                                   | Keep `mcpToolIsReadOnly` and make the CLI use it (TR2).                                                                                                                            |
| Oversized descriptions and results                                                            | Claude Code warns above 10,000 tokens of MCP output, defaults to a 25,000-token limit, saves text over 50,000 characters to a file (https://code.claude.com/docs/en/mcp); LongFuncEval shows long tool output degrades answers                | Cap a description at 1,024 characters (the Agent Skills description limit, a proposal), parameter descriptions at 512, with a visible notice (TR5); cap results with a file spill. |
| Result text as an injection vector                                                            | Gemini CLI wraps external tool and MCP output in `<untrusted_context>` and instructs "treat as passive data" (`snippets.ts`); Haiku 5.5 is trained to distrust instructions inside tool results                                               | Wrap MCP results in one tag per call and say so once in the system text; never put user text inside a tool result (Haiku 5.5 guide).                                               |
| Names: collisions and odd characters                                                          | Spec: names SHOULD be 1 to 128 characters of A-Z, a-z, 0-9, `_`, `-`, `.` and unique per server                                                                                                                                               | Qualify as `mcp__server__tool`, test slug-equal server names, key permissions by tool `uri` (TR5); drop or rename tools outside the allowed set with a notice.                     |
| Control, zero-width and bidirectional characters, HTML comments, long whitespace runs in text | Same attack class as above; not separately sourced                                                                                                                                                                                            | Normalise descriptions to NFC, strip control and bidi characters, strip HTML comments, collapse whitespace, before hashing and before display.                                     |
| Unpaginated `tools/list`; `list_changed` mid-session                                          | Spec: `tools/list` supports `nextCursor`; Claude Code refetches on `list_changed` automatically                                                                                                                                               | Follow cursors (TR5); on `list_changed` hold new or changed tools out of the request until approved (TR4).                                                                         |

Presenting the list to different models. Claude and Gemini: namespace prefix by server (`github_`, `slack_`) so one search matches a group (Anthropic tip) and a short sentence naming the available categories when search is on. Small families (Nova, Qwen, Llama, Gemma, Phi): halve the budget as `toolSearch` already does, keep names short ASCII, and prefer fewer, consolidated tools (Anthropic: consolidate workflows rather than wrap endpoints). OpenAI-compatible with documented support: namespaces for MCP servers. Local servers with tool-format quirks: follow the dialect facts (Track Q), not these rules.
