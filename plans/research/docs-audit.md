# Documentation audit: user-facing docs against what ships

Date: 2026-11-12. Read at `origin/main` 63e6e122d (merge of #764). Nothing was built: the findings come from reading the docs and the code, from three small scripts run with plain node (section 3.5), and from two live lookups (the VS Code Marketplace listing and the repository settings through `gh api`). `plans/ROADMAP.md` is not edited; section 6 holds the rows to apply.

Scope: `docs/**`, `README.md`, `PRIVACY.md`, `SECURITY.md`, `CODE_OF_CONDUCT.md`, `CONTRIBUTING.md`, the extension READMEs and Marketplace text in `extensions/vscode`, the CLI `--help` text and slash-command descriptions in `extensions/cli`, and help strings shown in the product. The ROADMAP and the research notes were reviewed track by track on 2026-11-11 and are out of scope here.

**Evidence marks.**

- **V**: I read the doc line and the code line in this session.
- **R**: the code reference comes from `product-review-controls-and-roadmap.md` (its own marks apply); I checked the doc side only.
- **M**: mention level only. A script found the name in a page; nobody checked the sentence around it.
- **unverified**: not traced.

Releases use even minors. "Next release" means **2.18.0**.

## Summary

The pages this fork wrote (permissions, command checks, audit trail, `cn serve`, run limits, terminal environment, workspace trust) are detailed, and every statement I checked against code held. The debt is elsewhere, in four places.

1. **The entry points say wrong things.** Three install pages said the extension is not on the VS Code Marketplace; it is, at 2.14.0, and one of the three is the text the Marketplace listing itself shows. `CONTRIBUTING.md` sends bug reports and feature ideas to the upstream repository. `SECURITY.md` and `PRIVACY.md` point at a private-vulnerability form that is switched off. Two `package.json` files point `bugs.url` at a disabled Issues page.
2. **The terminal agent has no documentation of its own.** `docs/` has three pages about it (`guides/cn-serve`, `cli/run-limits`, `guides/acp`) and no page that says how to install it, start it, or what its commands are. 21 of its 26 slash-command entries appear nowhere, `continuous review` appears nowhere, and `--policy`, the flag that sets permission levels, is not in any page.
3. **Headline features have no page.** The README's own list of what the fork adds includes Loop mode, subagents, checkpoints, queued messages and the toolbox drawer. None has a page that says what it is and how to start it. Loop mode has pages for budgets and for leaving and resuming, and no page that defines the autonomy levels or the default limits.
4. **Upstream text survives in what ships, not in the docs.** `docs/**` is nearly clean (19 capitalised "Continue" in 10 files, all legitimate or in one stray backup file). The leftovers are in `extensions/vscode/config_schema.json` (31 `docs.continue.dev` links and a sentence that says telemetry is collected, shown on hover), the CLI help text (six flags still say "from the hub"), `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`, and everything under `extensions/intellij`.

## 4. Information architecture

### 4.1 What the tree is organised around today

The top level is upstream's: one tab, "IDE Extensions", with Getting Started, Features (Agent, Chat, Autocomplete, Edit), Customize, Reference, Guides and Help. The fork's new pages were added where there was room:

### 4.4 Page template

For a feature or control page. Sections may be short; none is skipped.

1. **What it is.** One paragraph, with no history.
2. **Why you would use it.** The task it serves.
3. **How.** Steps for the GUI, then the command or the file. A real example that runs.
4. **Defaults.** A table: the setting, its default, where it is set (GUI, flag, file, environment), and which wins.
5. **Safety.** What it can do without asking, what still binds, and what a project file cannot change.
6. **Limits.** What is not built or not covered, stated plainly, as `permissions-page.mdx:41` and `hooks-trust.mdx:47` already do.
7. **Troubleshooting.** The messages a person will see, quoted exactly, and what each means.
8. **Related.** Three links at most.

Reference pages use a second template: one row per key or flag, with type, default, who can set it, and the version that added it.

### 4.6 Docs as tests

In order of value for the effort.

1. **Health check in CI.** The script of section 3.5 as `scripts/ci/docs-health.mjs`, run on any change under `docs/` or `docs-site/`: broken internal link or anchor, nav entry without a page, page in no nav and with no inbound link, unknown component, raw autolink, redirect to a missing page. It runs in under a second and needs no install.
2. **Shipped links.** Run `scripts/docs-links.js` in CI as a check, with `config_schema.json`, `extensions/cli/src` and the tutorial files added to `SCAN`. Fail on any `docs.continue.dev`.
3. **CLI help snapshot.** A test renders `--help` for the root command and each subcommand from the commander definitions and compares it with files in `extensions/cli/src/__snapshots__/help/`. A flag cannot change, appear or vanish without a diff a reviewer sees. Proposed row CO17 asks for the same test; this is its docs half.
4. **Generated reference pages.** The same definitions write `docs/cli/reference.mdx`; `package.json` writes the VS Code settings, commands and keybindings page. CI fails when the generated file differs from the committed one.
5. **Key coverage.** A test collects every key in the `config.yaml` schema, every `continuous.*` setting and every `CONTINU*` name read in shipped code, and fails when one is in neither a docs page nor an allowlist that gives a reason ("internal", "test only", "deprecated"). Today it would report 17 keys, 12 settings and 29 names.
6. **Examples that parse.** Every fenced `yaml` block with a `title` of `config.yaml`, `permissions.yaml`, `models.yaml` or `providers.yaml` is parsed by the real schema. Every fenced `bash` line that starts with `continuous` or `cn` is checked against the commander tree: the command exists and the flags are defined. This would have caught `cn login`.
7. **Vocabulary lint.** A list of banned strings in user docs with the replacement: `YOLO`, `Auto mode`, `Continue CLI`, `the hub`, `~/.continue/` not followed by "older". #699 added a guard for the IDGAF rename; this extends it to the README files.
8. **A real build on pull requests.** `docs-gh-pages.yml` builds only on push to `main`, so a page that breaks the MDX compile is found after merge. Running `npm run build` in `docs-site` on pull requests that touch `docs/**` closes that; it costs an install.
