## 3. Designs for the open rows that matter

### 3.1 Model facts: lifecycle, capabilities, limits (K22 rest, K24, K3 rest, PL12, PL4)

**Problem in user terms.** A person on `claude-opus-4-5-20251101` should be told before 2026-11-24 that it may retire, a person on OpenAI or OpenRouter should be told the same from those providers' own dates, and the setup flow should offer the reasoning levels and token limits the provider says a model has instead of a hard-coded guess.

**Design.**

1. One shape for "what the provider's list says", `ListedModelFacts { id, lifecycle?, deprecatedAt?, retiresAt?, notSoonerThan?, maxInputTokens?, maxOutputTokens?, efforts?: string[], thinkingTypes?: string[], toolCalling?: boolean, source, fetchedAt }`, in `core/util/listedModelFacts.ts` (pure, GUI-safe). Four readers feed it: Anthropic (`lifecycle`, `deprecated_at`, `retires_at`, `capabilities.effort`, `thinking.types`, `max_input_tokens`, `max_tokens`), OpenAI (`shutdown_date`), OpenRouter (`expiration_date`, `supported_parameters` from the #690 file), Mistral (`capabilities`). Field names are from `providers-models-import.md` section 2.1 (fetched 2026-11-11); OpenAI and Mistral field names were not re-read today and must be checked against a live response before coding.
2. `modelRetirement.ts` already merges a checked-in table with live fields; extend its input with the `ListedModelFacts` rows, keep "provider anthropic only" for the table (dates apply to Anthropic-operated platforms; Bedrock and Google-managed Vertex set their own, per the deprecations page of 2026-11-12) and allow the live rows to carry their own provider. No new network call: only when the person already pressed Test connection, refreshed a list or ran `continuous models refresh`.
3. K24: in `fetchAnthropicModels`, use `ANTHROPIC_LIST_VERSION` (already defined in `anthropicSurfaceTest.ts`) with the existing fallback to `2023-06-01` on a 400, page with `after_id` until `has_more` is false (today `limit=100` silently truncates), and pass `efforts` and `thinkingTypes` into the add-model flow so the reasoning variants are generated, not typed. Keep the Messages path on its current version (K23's condition).
4. K3 remainder: Bedrock quota. AWS publishes the per-account applied value only through Service Quotas ("To check the values that apply to your account, use Service Quotas", quotas page, 2026-11-12) and keeps separate pools for `bedrock-runtime` and `bedrock-mantle`. Read with `ListServiceQuotas` for the Bedrock service code; the service code string and the quota-name patterns for per-model TPM were **not verified** here and the first step is a free read on the owner's account (memory note: Claude 5.5 and Fable at 0 TPM on the torgate account). Show "not enabled" when the applied value is 0 (matches the ROADMAP wording). `servicequotas:ListServiceQuotas` is a new IAM permission; the failure path must be silent, as `GetFoundationModelAvailability` already is.
5. PL12: write the same listed facts into `surfaceFacts` as `declared` rows with `staleAfter`; never enable a feature alone (existing evidence floor).

**Alternatives.** Scrape the deprecations page at build time (already the table's source; a human step, keep); use models.dev or LiteLLM as a runtime source (rejected: third-party assertions, LiteLLM's repo is MIT except `litellm/enterprise/` which has its own licence, GitHub LICENSE page fetched 2026-11-12; models.dev licence stated MIT in the 2026-11-11 note).

**Risks.** Privacy: the list call carries the user's key to the provider's own host, as Test connection does; nothing to a third party. "Not sooner than" must stay `possible`, never "retired". Backward compatibility: a failure to read capabilities must leave today's behaviour.

**Tests.** Unit: fixtures per provider list with the fields present, null and absent; retirement date arithmetic around the 60-day edge; paging fixture with two pages. GUI: chip text for the new providers, axe on any new line. No sandbox needed.

**Size.** S for item 1 to 3, M for items 4 and 5. **Acceptance.** An OpenAI model with `shutdown_date` inside 60 days shows the chip; the Anthropic variants for a model come from `capabilities.effort`; a list of 150 models is not truncated; a Bedrock account with an applied quota of 0 shows "not enabled" in the picker; no request is made unless the person triggered one.

### 3.2 Prompt profile as a setting (K1b, A6, K19)

**Problem.** The profile is invisible: a person who gets the tailored text cannot see or change why (#366).

**Design.** Two steps.

1. K1b: `promptProfile: full | short | tailored` on a model in `config-yaml/src/schemas/models.ts`, read by `promptProfile(model)` in `turns.ts` before the regex rules and after the environment override. The CLI reads the same field (`segmentDump.ts` already reports the profile).
2. A6: in `ModeModelsTable.tsx` the Prompt select gains "Tailored" and the "Default" option's label becomes "Default (short for this model)" by calling the same resolver, so the label cannot drift from behaviour. The Settings > Models row for a model shows the profile with the reason (`rule: qwen coder`, `override`).
3. K19 later folds the resolver into `DialectPreset` with source and evidence, as the ROADMAP says; do not do it first because K1b and A6 need nothing from it.

**Alternatives.** An environment variable only (today; rejected, webview has no environment, same reason as K21). A global switch (rejected: the profile is per family).

**Risks.** A wrong override on a small model costs plan quality (K9 measured six of six against four of six); show a one-line description beside the select. Backwards compatible: an unset field changes nothing.

**Tests.** vitest for resolution order; `ModeModelsTable` view test for the new option and label; the golden segment dump unchanged for an unset field. **Size.** S plus S. **Acceptance.** A model with `promptProfile: short` sends the short text in IDE and CLI; the Settings label names the profile and its source.

### 3.3 One switch for Plan and Act models (A7)

**Design.** In `ModeModelsTable.tsx` show a single checkbox "Use different models for Plan and Act", default off. Off: Plan and Agent share one list and one default, the other five uses (loop, replan, subagent, reviewer, chat) follow the Agent model and sit under a collapsed "Advanced" heading. On: today's table. Turning it off with different defaults set shows a one-line confirmation ("Plan will use <Agent default>") before Save, since the write changes `modeModels.plan`. State derives from config (`plan.model !== agent.model`), nothing new is stored.

**Alternative.** Hide uses by role instead of by switch (rejected: the prior-art table in `providers-models-import.md` section 5 shows Cline's toggle is the one pattern people already know).

**Tests.** Draft logic in `modeModelsDraft.ts` (unit); view tests for both states; axe and screenshots at 300 px. **Size.** S. **Acceptance.** A new person sees one picker; a person with distinct Plan and Agent defaults sees the switch on, and no value is lost.

### 3.6 Bedrock paths (K25, K26, PL10, PL19)

**Facts (AWS docs, read 2026-11-11 and 2026-11-12).** `bedrock-runtime` and `bedrock-mantle` are two endpoints with separate per-model quotas; AWS recommends `bedrock-runtime /openai/v1` for new applications and Mantle only when a model or capability is missing; `bedrock-runtime` has no `/models`; closed-weight OpenAI models there need inference profile ids; short-term API keys last up to 12 hours and only in the Region that created them.

**Design.** K25: make `BedrockMantle` host-configurable through a `surface: runtime | mantle` option (default stays `mantle` so existing configs do not move), build the base URL from it, route model id validation through the catalogue the K3 cache already holds. Do not change the default until the sweep in MR10 shows which of our Bedrock matrix models answer on `runtime /openai/v1` (experiment E3 in the 2026-11-11 note, about 1 to 3 USD). K26: short-term key refresh needs `@aws/bedrock-token-generator` (owner decision; adds a dependency to a bundled package and supply-chain review under Track CI); the cheaper first step is the setup-flow warning on a long-term key and the streaming check in Test connection (PL10). PL19: a spike that passes our request handler to the SSO and STS providers behind the existing CONNECT-proxy fixture (`Bedrock.tls.test.ts`); no product change until the spike shows the SDK ignores it.

**Risks.** Two quota pools means a model can be throttled on one surface and free on the other; say so in Test connection. Region mismatch for short-term keys gives a confusing 403; name the key's Region in the error.

**Size.** K25 M, K26 S to M (decision), PL10 S, PL19 S.
