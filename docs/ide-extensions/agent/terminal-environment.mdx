---
title: "Command environment"
---

Commands the agent runs do not inherit secrets from your environment by default. API keys, tokens, passwords, cloud credentials and agent sockets are removed before a command starts. This applies to terminal commands, loop checks, hook commands, background jobs, and the host variables passed to a stdio MCP server. You choose the policy in **Settings, Tools, Commands and secrets**: three options, each with what it does, a live list of the variable names (never values) your editor's environment has that the chosen option would remove or keep, and a box for variables to pass through. You can also edit `config.yaml` directly:

```yaml title="config.yaml"
terminal:
  environment: inherit
```

`CONTINUE_TERMINAL_ENV=inherit` does the same and takes precedence over `config.yaml`; while it is set, the settings control is read-only and says why. In the terminal agent, `continuous terminal-env show` prints the effective mode, where it comes from, and the names it removes.

## Only your own settings can loosen it

`inherit`, `terminal.passEnv` and `terminal.allow` are honoured only when they come from your own user-level `config.yaml` (which is where the settings control writes) or from `CONTINUE_TERMINAL_ENV`. The same keys in an assistant, a hub configuration or a folder you opened are ignored, and a notice in the settings control and the config errors says so. A tighter value (`allowlist`) is accepted from anywhere, and cannot be loosened by anything except your own settings. If you relied on `inherit` coming from an assistant, commands now run in `scrub` mode until you set it yourself.

## Modes

| `terminal.environment` | Result |
| --- | --- |
| `scrub` (default) | Everything is passed except names that look like secrets and values that are URLs with credentials. |
| `inherit` | Everything is passed, as in earlier versions. |
| `allowlist` | Only basics such as `PATH`, `HOME`, `USERPROFILE`, `TEMP`, `SystemRoot`, `ComSpec`, `PATHEXT`, `LANG` and `TERM`, the WSL variables, and the names in `terminal.allow`. |

`CONTINUE_TERMINAL_ENV` accepts the same three values.

## What is removed

In `scrub` mode these names are removed (matching is case-insensitive on Windows): `*API_KEY`, `*_KEY`, `*TOKEN`, `*SECRET`, `*PASSWORD`, `AWS_*`, `AZURE_*`, `GCP_*`, `CONTINUOUS_*`, `CONTINUE_*`, `ANTHROPIC_*`, `OPENAI_*`, `SSH_AUTH_SOCK`, `DOCKER_HOST`, `DATABASE_URL`, and any variable whose value is a URL containing a user name or password. `PATH`, `HOME` and the other non-secret basics always pass.

## Pass a variable through

List exact names in `terminal.passEnv`. They pass in every mode:

```yaml title="config.yaml"
terminal:
  passEnv:
    - GITHUB_TOKEN
    - AWS_PROFILE
```

The agent is told that secrets are not passed and that you can allow a name here, so it can ask you to.

## MCP servers

A stdio MCP server's own `env:` block is your explicit configuration and is passed as written, including keys. Only the variables the host passes implicitly are scrubbed.
