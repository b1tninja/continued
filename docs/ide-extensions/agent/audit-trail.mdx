---
title: "Audit Trail"
---

Continuous writes a local record of each tool call: what was decided, who decided it, and how the call ended. The record is on by default, masked, capped in size and age, and never leaves your machine.

```bash
continuous audit list --decision deny --since 2026-11-01
```

## What is recorded

Each call produces a `decision` line when it is decided and an `outcome` line when it finishes, joined by the call id. A call that asks and is then answered has two decisions: the ask, then the person's answer or the reviewer's.

| Field                         | Content                                                                                    |
| ----------------------------- | ------------------------------------------------------------------------------------------ |
| Decision                      | `allow`, `ask` or `deny`, and who decided: rules, the reviewer model, you, or the system   |
| Rule and source               | The rule as written in config.yaml, and which check decided (deny rule, protected path, level) |
| Reason                        | The sentence shown to you or the agent, clipped to 300 characters                          |
| Reviewer                      | Model, latency, token usage, category and whether the verdict was reused                   |
| Arguments                     | The masked arguments, clipped to 2,000 characters, with a hash of the masked text and the original length |
| Outcome                       | Whether it ran, exit status, duration, output size and a hash of the masked output         |
| Agent                         | Which agent made the call: an id, a kind, and when known a role, a mode and the parent's id |

Tool output is not stored, only its size and hash. Assistant text is not stored.

### Agent identity

Decision, outcome and turn records carry an `agent` field: `id` (`main-<session>`, `sub-<toolCallId>`, `worker-<itemId>` or `bg-<taskId>`), `kind` (`main`, `subagent`, `loop-worker` or `background`), and optionally `role` (the subagent definition's name, such as `Explore`, or `item 3` for a Loop worker), `mode` (the permission mode) and `parentId` (the agent that started it). Each value is masked and clipped to 80 characters, and no prompt is stored. Records written before this field existed have none and read as unknown. Stuck-agent detection counts each agent's turns on its own.

In the IDE, a call is recorded when it is evaluated and when it runs. Edit tools are recorded as allowed unless a rule or protected path stops them; the diff you accept or reject is not part of the audit.

## What is masked

Arguments, reasons and error lines are masked before they are written or hashed. Recognised credentials (API keys, cloud and GitHub tokens, private keys, JWTs, secrets on a command line) become `«masked:kind»`. Masking is best effort: a secret in a shape that is not recognised is written as typed, which is why the files are private to your user (`0600`) and local.

## Where it is stored

```
<global dir>/audit/<yyyy-mm>/<session>.jsonl
```

The global directory is `~/.continuous` unless `CONTINUOUS_GLOBAL_DIR` points elsewhere (an existing `~/.continue` is still used). A file that reaches 20 MB continues in `<session>.1.jsonl`. Files older than 30 days are deleted when the IDE or CLI starts. A write that fails (full or read-only disk) is reported once and never stops a tool call.

## Read it

```bash
continuous audit list [--session <id>] [--decision allow|ask|deny|reviewer] [--tool <name>] [--agent <role|id|kind>] [--since <date>] [--until <date>] [--limit <n>] [--json]
continuous audit show <session> [--json]
continuous audit inbox [--agent <role|id|kind>] [--session <id>] [--since <date>] [--json]
continuous audit suggest [--decision allow|deny] [--min <n>] [--max-age-days <n>] [--max-mb <n>] [--max-rows <n>] [--verbose] [--json]
continuous audit prune [--days <n>] [--dry-run]
```

`--decision ask` matches calls that asked at any point, including those you then approved. `--decision reviewer` matches calls the reviewer model decided. `--agent` keeps calls whose agent role, id or kind equals the value exactly (`Explore`, `sub-call_1`, `loop-worker`). `--json` prints one array: rows for `list`, raw records for `show`. The `list` row shows the agent's role, or its kind when it has no role.

### Inbox

`continuous audit inbox` lists the calls that asked and have no outcome yet, oldest first, with the agent that is waiting on each: `2026-11-11 09:14:02  Explore [agent] under main-s1  runTerminalCommand  git push origin topic`. A session that ended with a question open (a crash, a closed window) looks the same, so each line carries its time. It prints "Nothing is waiting for an answer." when the list is empty.

### Suggested rules

`continuous audit suggest` reads asks you answered the same way again and again and prints candidate rules, each with how many times it was allowed or refused, the date range, the agents involved, a risk note, examples and the `continuous permissions add ...` command that would apply it. It changes nothing; applying a rule goes through the [Permissions page](/ide-extensions/agent/permissions-page) confirmation. A pattern needs 3 answers by default (`--min`). The read is bounded: at most 90 days (or your retention, if longer), 32 MB and 100,000 records unless you raise `--max-age-days`, `--max-mb` or `--max-rows`, and the output says when a limit cut the read. `--verbose` also lists candidates that were withheld and why.

## Measure the reviewer on your own work

Shadow mode runs in the terminal agent and in the IDE. It asks the reviewer model about calls it was not asked about, and records what it would have decided next to what actually happened. It never changes a decision, never holds a tool call up (it runs alongside the call and is dropped if it is slow), and sends the reviewer the same masked text the reviewer always gets. It is off until you turn it on in your own global `config.yaml`; a workspace or assistant file cannot enable it. A dollar budget is required:

```yaml
audit:
  shadowReviewer:
    enabled: true
    budgetUsd: 0.25
    timeoutMs: 5000
```

`budgetUsd` caps all shadow reviews kept in the audit trail (30 days by default). Once reached, no more run. A reviewer model with no known price stops after one review, because a budget cannot be held to it. In the IDE it reviews calls from the main chat agent that settle by rules or that you answer; file edits (whose answer is a diff) and calls from subagents, Loop workers and MCP apps are not shadowed. The budget is counted per process, so an IDE and a terminal agent running together can each spend what is left. There is no Settings toggle; the switch is read only from `config.yaml`. It needs a reviewer model (see [the reviewer](/customize/model-roles/reviewer)) and the audit trail on.

```bash
continuous audit shadow [--session <id>] [--model <name>] [--since <date>] [--until <date>] [--limit <n>] [--json]
```

The report shows how often the reviewer agreed with the real decision, a matrix of real decision against shadow decision, counts and cost by model, and the disagreements with their masked arguments.

## Turn it off

In the global `config.yaml`:

```yaml
audit:
  enabled: false
  retentionDays: 30
```

Or in the environment, which takes precedence:

```bash
CONTINUE_AUDIT=off
```

With it off, nothing is written. Existing files stay until they age out or you run `continuous audit prune --days 0`.
