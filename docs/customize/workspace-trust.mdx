---
title: "Workspace Trust"
---

Configuration that comes with a folder is not applied until you trust the folder. A repository you cloned can ship files that start programs, point a model at another server or read your secrets, so Continuous holds them back and says so in the config errors.

## What waits for trust

These files, under the folder's `.continuous/` (or the older `.continue/`) directory, are not applied until the folder is trusted:

| Files                                           | Held back                                                           |
| ----------------------------------------------- | ------------------------------------------------------------------- |
| `mcpServers/*.yaml`, `*.yml`, `*.json`          | MCP servers are not started, and their secret values are removed |
| `models/*.yaml`, `*.yml`                        | Model blocks are left out, so they get none of your secrets          |
| `providers.yaml` and `models.yaml`              | Ignored, in the editor and in the terminal agent                     |
| `data/*.yaml`, `*.yml`                          | Data destinations are left out                                       |
| `*.continuousrc.json`, `*.continuerc.json` at the repository root | Not merged; a symlinked file is always ignored        |

Your own configuration always wins a name collision: a folder cannot replace a model, provider or MCP server you already have by giving it the same name. A server from a folder also does not receive the sign-in you saved for your own server at the same URL.

Trust is recorded in your Continuous folder, never in the project, against a fingerprint of the files as they are now. Editing one of them asks again.

## Trust a folder in VS Code

When a folder in a workspace you trusted in VS Code has configuration that was held back, a dialog lists the files and offers **Trust this folder**. Dismissing it leaves the folder untrusted. In a workspace VS Code has not trusted, the dialog is not shown and nothing from the folder is applied.

## Trust a folder in the terminal agent

```bash
continuous project          # list what the folder ships and whether it is trusted
continuous project trust    # show the files, then ask
continuous project revoke   # remove trust
```

`continuous project trust` asks `Trust them? [y/N]`. With no terminal to ask on, it does not trust the folder unless you pass `--yes`. To use a folder's configuration for one run only, without recording trust:

```bash
continuous --trust-project-config
```

Trust given in VS Code and by `continuous project trust` is the same record.
