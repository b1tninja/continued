---
title: "cn serve"
---

`continuous serve` starts the terminal agent as an HTTP server that takes messages, approvals and loop answers. Anything that can reach the port can act as you, so it listens on loopback by default, checks the Host and Origin of every request, and requires a token you choose when it listens beyond this computer.

```bash
continuous serve --port 8000
```

| Option                        | Default       | Meaning                                                                                                  |
| ----------------------------- | ------------- | -------------------------------------------------------------------------------------------------------- |
| `--port <port>`               | `8000`        | Port to listen on                                                                                        |
| `--host <host>`               | `127.0.0.1`   | Interface to listen on. Anything but loopback listens beyond this computer, needs `--token`, and prints a warning |
| `--token <token>`             | none          | Bearer token every request must carry, at least 16 characters. Also read from `CONTINUOUS_SERVE_TOKEN`. Optional on loopback, required elsewhere |
| `--allow-origin <origin...>`  | none          | A browser origin that may call the server, such as `http://localhost:3000`. Exact match, no wildcard     |
| `--timeout <seconds>`         | `300`         | Inactivity timeout                                                                                       |

## Access token

A token is your choice. On loopback (the default) the server needs none and does not make one up: a request that passes the Host and Origin checks is answered. Pass `--token` or set `CONTINUOUS_SERVE_TOKEN` to require one; it must be at least 16 characters and is never echoed or written to the log. With `--host` set to anything but loopback the token is required.

| Listening on | No token                                   | Token given                                                  |
| ------------ | ------------------------------------------ | ------------------------------------------------------------ |
| Loopback     | Starts. No bearer check                    | Starts. Every request needs the token                        |
| Elsewhere    | Refused: message on stderr, exit status `2` | Starts with a warning. Every request needs the token        |

Send the token in the `Authorization` header:

```bash
export CONTINUOUS_SERVE_TOKEN="$(openssl rand -hex 24)"
continuous serve
curl -H "Authorization: Bearer $CONTINUOUS_SERVE_TOKEN" http://127.0.0.1:8000/state
```

Setting it in the environment keeps it out of the process list. A token in the query string is not read: URLs end up in logs and history, so `?token=...` gets `401`. A request without a valid token gets `401`; an address that fails repeatedly is held off with `429` for a minute. The terminal agent in remote mode and `continuous agents list` send `CONTINUOUS_SERVE_TOKEN` when it is set.

An approval that arrives over a server with no token has no authenticated person behind it, so the audit trail records it as the system's (`by: system`). With a token it is recorded as `by: person`, as before.

### When the server refuses to start

`continuous serve` does not start with an option it cannot honour. It prints one line on stderr saying what was refused and what to change, and exits with status `2` (the usage-error status, as in `continuous secrets scan`). The line never contains a token. The cases are a non-loopback `--host` with no token (pass `--token` or set `CONTINUOUS_SERVE_TOKEN`, or use `--host 127.0.0.1`) and a token shorter than 16 characters. Check it in a script with `continuous serve --host 0.0.0.0; echo $?`.

## Host and Origin checks

These apply before the token is checked, whatever the token setting. A Host that does not match gets `403`, not `421` as in earlier versions.

- The `Host` header must be the address the server is bound to: `127.0.0.1`, `localhost` or `[::1]` on loopback (with this server's port, when the header has one), or the `--host` value elsewhere. Anything else gets `403`. This stops a DNS-rebinding page from reaching the server.
- A request with an `Origin` header gets `403` unless the origin is listed with `--allow-origin`. Browsers send `Origin`; `curl` and other local clients do not. A listed origin is answered with its own name in `Access-Control-Allow-Origin`, never `*`. The server has no WebSocket route and refuses every upgrade request with `403`.

## Limits and masking

A request body over 1 MB gets `413`. Each address is limited to 1200 requests a minute (`429`). `GET /state` and `GET /diff` pass what they return through the display masker and the secret scanner, so a key in the conversation or in a diff is shown as a placeholder.

## Agents

`GET /agents` lists the agents of the session: the session itself, the subagents it started and the workers of a Loop wave. It answers the same Host, Origin and token checks as the other routes.

```bash
curl -H "Authorization: Bearer $CONTINUOUS_SERVE_TOKEN" http://127.0.0.1:8000/agents
continuous agents list              # the same list as a tree
continuous agents list --json       # the JSON as the server sent it
continuous agents list --url http://127.0.0.1:9000 --token "$CONTINUOUS_SERVE_TOKEN"
```

`GET /state` returns the whole conversation and the arguments of a pending permission. `GET /agents` does not: it is built from an allow-list of names, states and numbers, and has no field that could hold a prompt, a command, a URL, a file's contents or an agent's own words.

Each node has:

| Field                         | Meaning                                                                                                              |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `id`, `parentId`, `rootId`    | Where it sits in the tree. The session is the root                                                                   |
| `kind`                        | `main`, `subagent`, `loop-worker` or `external-reserved` (no producer yet)                                           |
| `role`, `mode`, `model`       | The agent's name (or `item 3` for a worker), its permission mode and the model's title                               |
| `state`                       | `running`, `waiting-approval`, `blocked`, `done`, `failed`, `stopped` or `over-budget`                               |
| `blockedOn`                   | What a waiting agent waits on, as a kind only: `approval`, `question`, `slot`, `dependency` or `budget`             |
| `activity`                    | One of a fixed list of phrases: `reading files`, `searching`, `editing`, `running a command`, `fetching`, `working`, `waiting for you` |
| `startedAt`, `endedAt`        | Milliseconds since the epoch                                                                                         |
| `tokens`                      | Input, output, cache read and cache write tokens                                                                     |
| `cost.self`, `cost.subtree`   | USD of this agent alone and of it with everything below it, or `"unknown"`                                           |
| `workspace`                   | For a worker, the worktree's folder name, never its path                                                             |
| `returnedLength`              | How long the agent's answer was. The answer is not kept                                                              |

Cost is never guessed. A model without a price makes the agent's cost `"unknown"`, and so the cost of everything above it. The session's total already holds what its subagents and workers spent, so the session's own cost is the total minus theirs, not the total plus theirs.

`needsYou` lists the ids of agents waiting for you, and `totals` counts agents by state. If the list cannot be built, the answer is an empty list with a fixed `error` sentence, never the exception.

In the IDE the same list appears above the chat input once an agent has started, as a read-only tree you can collapse. Stop stays on a subagent's card and in the Loop inbox.

The agent map observes; it does not change what agents do or ask. Subagents in the terminal agent run one at a time, so a second one shows as `blocked` on a `slot` until the first ends. A Loop worker's activity and approvals are not shown yet, and its cost is `"unknown"`.
